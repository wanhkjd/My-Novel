# 公开评论展示身份

## 对原审查结论的更正

原报告依据 commentUser = username 推断匿名 HTTP 响应会暴露完整手机号，但遗漏了 BookCommentRespDto.commentUser 上的 UsernameSerializer 注解。

本次使用真实 BookController、BookServiceImpl、WebConfig 和 JacksonConfig 的匿名 MockMvc 请求验证：修复前，测试手机号 13800000000 已被序列化为 1380****000，HTTP 响应不包含完整手机号。因此不能把原报告的完整手机号泄露描述当作已确认事实。该基线测试在修复前后均通过，保留在回归套件中。

实际确认的问题：

- 评论始终使用登录账号而非用户设置的昵称，仍暴露部分账号信息。
- 完整登录账号进入响应 DTO，仅依赖最终的 Jackson 字段注解遮罩；非 Jackson 消费者拿到的还是原值。
- 旧遮罩直接 substring，长度不足的历史账号导致匿名评论请求返回 500。
- 评论对应用户记录缺失时，映射阶段空指针导致整个请求失败。

## 修改

在 BookServiceImpl 组装公开评论时确定展示身份，而不是把原始登录账号放进 DTO：

1. 优先使用非空昵称并去掉首尾空白。
2. 昵称包含该用户登录账号、包含常见 11 位大陆手机号片段（1[3-9][0-9]{9}）、为空或用户记录缺失时，统一显示“书友”。不会回退到 username，也不从手机号生成带号码片段的默认名。
3. 用户记录缺失时保留评论，头像返回 null。
4. 移除评论字段的 UsernameSerializer 注解，并删除已无源码调用的旧序列化器，避免把短昵称错误截取或再次遮罩。

公开字段名、commentUserId、评论 ID/正文/时间、有效头像和 Long 转字符串的全局规则不变；前端仍读取 commentUser，不需要改动。最新评论仍按书籍及已审核状态过滤、按创建时间倒序取 5 条。

这是公开展示身份的局部映射修复，没有新增独立转发层，也没有修改用户存储记录、注册规则或管理员资料查询。

## 回归测试（2026-10-11）

新增 PublicCommentPrivacyTest 共 25 项：

- 匿名 HTTP 不暴露完整登录手机号的旧版基线。
- 正常中文、英文、短昵称、Emoji 和首尾空白昵称正常展示；服务返回的 DTO 同样不依赖序列化遮罩。
- 默认手机号昵称、包含手机号的旧昵称、空昵称及与历史登录账号相同的昵称使用非敏感占位值。
- 空或短历史登录账号不再触发遮罩越界。
- 缺失用户、空评论、多用户批量映射与评论顺序。
- 公开字段及日期格式保持兼容，生产 JacksonConfig 的 Long 字符串序列化仍生效。
- 书籍/审核筛选、创建时间倒序和 5 条限制不变。

结果：

- 修复前：25 项中 4 项通过，20 个 failure、1 个 error。error 为用户记录缺失后的空指针；部分 failure 明确复现短账号返回 HTTP 500。
- 修复后，独立提交分支：132 项通过，0 失败、0 错误、0 跳过。
- 修复后，包含用户现有未提交改动的隔离集成副本：155 项通过，0 失败、0 错误、0 跳过；额外测试不纳入本次提交。

使用 JDK 21、Maven 离线依赖执行：

~~~shell
mvn "-Dtest=*,!EsRealSyncTest" test
~~~

数据库查询使用 mock，用户和评论均为测试夹具；没有读取或修改真实用户数据，没有调用模型或真实 Redis/Elasticsearch。排除会写真实 Elasticsearch 的 EsRealSyncTest。

## 生效与限制

源码同步后需重新构建并重启后端。构建仅在独立工作树和临时集成副本执行，未改写正在运行的 target/classes；原有阅读历史等未提交修改保留，未合并或推送 main。

本次承诺限于系统生成的公开评论展示身份，不是任意文本的通用隐私检测器：不审查用户主动写入评论正文/头像 URL 的联系方式，也不声称覆盖所有地区号码、带分隔符号码或其他个人信息。commentUserId 为现有评论归属字段，保持兼容，不把账号标识改为匿名化 ID。
