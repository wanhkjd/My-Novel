# 用户封禁执行规则

- 普通用户 user_info.status：0 为正常，1 为封禁；管理员 sys_user.status 的含义不同，不共用判断。
- 登录先验证密码，再拒绝被封禁的用户，不生成新 token。
- 前台与作家端共用 authSSO；只有认证通过后才写入 UserHolder。
- 封禁使用业务错误 A0202（用户账号已被封禁），不冒充登录过期 A0230。现有前端请求处理会显示错误并拒绝 Promise，无需修改公共请求框架。

## 为什么认证不读取缓存

只在封禁后删除缓存仍存在竞态：旧查询可能在删除之后回填正常状态，使后续请求继续放行。
因此 getUserForAuth 按主键直接读取数据库；getUser 保留原有缓存读取接口，不用于权限决策。
代价是每次受保护请求增加数据库点查，换取不依赖缓存 TTL、失效成败或并发回填的封禁判断。

管理员修改状态仍清理用户资料缓存。更新使用事务，Redis 缓存管理器已启用 transactionAware，缓存失效在成功提交后执行，回滚不清缓存。
非法状态和不存在的用户返回业务错误，不报告操作成功。

## 边界

- 封禁阻止后续认证，不追溯取消已经通过认证、正在执行的请求或 AI 生成。
- 解封恢复访问，既有有效 token 可以再次使用；没有引入 token 永久吊销或细粒度 RBAC。
- 作家账号自身的独立封禁策略不在本次范围内；本次覆盖普通用户封禁对作家端入口的限制。

## 2026-10-11 本地运行服务联调

在同步修复并重新构建、重启后端后，通过前端 localhost:2048（代理至后端 8888）完成真实 API 与浏览器验证，而非 mock 响应。使用新建专用读者账号，不操作已有用户；验证结束已解封恢复正常。

- 正常状态：登录、读者资料和作家状态入口均返回 00000。
- 管理后台封禁后：同一枚封禁前签发的 token 访问读者资料、作家状态和作家资料入口均返回 A0202。
- 封禁期间：正确密码登录返回 A0202，且不签发 token；错误密码仍返回 A0210。
- 浏览器登录页展示“用户账号已被封禁”，未报告登录成功。
- 管理后台解封后：同一枚旧 token 访问读者资料和作家状态恢复 00000，重新登录成功；原浏览器登录会话也恢复个人资料访问。

共记录 11 次 API 检查。此联调没有在真实环境主动制造并发陈旧缓存回填；该竞态仍由 UserStatusCacheTest 覆盖。新建账号未注册作家，本轮验证的是作家入口鉴权，不包含作品发布流程。

与当前原项目已有改动一起回归：后端 69 个测试通过（排除 EsRealSyncTest），前端 41 个测试通过。密码、token 和其他用户资料不写入文档或 Git。
