# 章节写入一致性修复

## 问题与范围

同一本书的发布、编辑、删除原来分别读取书籍/章节快照后，写回绝对总字数。并发请求可能丢失另一个请求的字数变化，发布还可能分配相同章节号。编辑/删除以详情缓存作为写入依据，即使请求不并发，旧缓存也可能造成错误。

删除最后一章时，原来的 `updateById` 默认忽略 null，不能真正清空 `last_chapter_update_time`。发布时还把更新时间设置到已插入的章节对象而不是书籍更新对象。

已核实：`AmqpMsgManager` 原本就在事务提交后发送消息，并非“事务内提前发消息”。本次保持此实现。

## 实现与保证

- 三个章节写入口使用同一书籍行的 `SELECT ... FOR UPDATE`，直到事务提交/回滚才释放。不同应用实例连接同一主库时也协调在同一个数据库锁上；不同书籍不使用全局锁。
- 编辑/删除第一次普通查询只定位不可变的 bookId；随后按“书籍 → 章节”的统一顺序加锁，并重新读取章节。等待期间已经删除的章节返回 A2002，不重复减字数。
- 分配章节号、选取最新章节均使用当前读。MySQL InnoDB 默认 REPEATABLE READ 下，不能用锁前建立的普通快照代替这些 FOR UPDATE 读取。
- 锁定查询禁用 MyBatis 二级缓存并清理会话缓存，避免把缓存命中当作真正的加锁读取。
- 写权限从当前数据库书籍记录校验；无作家身份/非本人为 A0301，缺失书籍/章节为 A2002。事务内失败回滚，不保留半次章节修改。
- 删除最后一章显式清空末章时间，并保留原约定的 lastChapterId=0、lastChapterName=""。发布同步更新书籍时间。

## 缓存取舍

本轮选择正确性优先：停止 `getBookInfo`、`getChapter`、`getBookContent` 的缓存读取和回填；原类名及 eviction 入口保留供现有调用方兼容。章节写操作不再无意义地访问这些旧缓存。详情直接按数据库的事务可见性读取。

仅改成 afterCommit eviction 并不充分：提交前已开始的旧数据库读取，仍可能在清缓存后完成并重新填入旧值。绕过这三类可变详情缓存后，这种加载不会污染后续请求；旧 Redis/Caffeine 条目也不会被新版 getter 读取，无需清空用户 Redis。

**成本**：书籍详情、章节元信息和正文请求的数据库读取量会上升。榜单、分类、推荐所用最新 ID 列表等缓存不变，仍按原 TTL 最终一致。后续若实际吞吐需要恢复正文缓存，应采用持久化版本键等一致性方案并压测，不能直接恢复原来的章节 ID 长期缓存。

## 保证边界

- 本次覆盖本后端的三个作家章节写入口，不自动修复历史已错误的总字数。
- 爬虫、手工 SQL、其他后端版本若同时修改同一本书，必须遵守相同书籍锁协议；本次未改爬虫，也未声称能约束所有外部写入。
- 不保证一整个详情响应的多次查询来自同一快照；并发中已经开始的读取可能返回较早数据，但不会通过本次停用的缓存把旧数据扩散到后续请求。
- 全部应用实例需部署新版；仍运行旧代码的实例仍可能读旧缓存或无锁写入。
- 当前配置的书籍/章节是单表，正文在同一数据源分表。本次未验证跨数据源分布式事务。
- MQ 保持原来的提交后发送，不增加 outbox/重试/恰好一次保证；提交后 MQ 故障仍属于既有的消息可靠性问题。

## 验证

新增 53 个用例：

- `ChapterWriteConsistencyTest`：33 个用例，使用真实 Spring 事务代理、MyBatis mapper、H2 MySQL 模式内存库和生产章节号唯一约束。用 latch 固定锁等待时序，覆盖并发发布、不同/同章节编辑、编辑/删除交错、删空末章、权限/缺失记录、已执行 SQL 后回滚、不同书籍独立提交。
- `MutableBookReadConsistencyTest`：13 个用例，真实 Spring 缓存代理 + 内存 CacheManager，验证旧条目绕过、冷读不回填、旧加载完成后的下一次读取、删除，以及保留列表缓存/旧 eviction 入口。
- `ChapterLockSqlTest`：3 个用例，使用当前依赖中的 ShardingSphere MySQL parser 解析实际 mapper SQL，确认 FOR UPDATE / LIMIT 能被识别，锁查询不使用 MyBatis 缓存。
- `BookChangeNotificationTransactionTest`：4 个用例，实际事务提交、异常回滚、rollback-only 和关闭 MQ 场景；broker 为 mock。

2026-10-11 执行 `mvn '-Dtest=*,!EsRealSyncTest' test`：

- 独立分支：185 个测试，0 失败、0 错误、0 跳过。
- 包含用户已有阅读历史、AI 流式代码等未提交改动的独立集成副本：208 个测试，0 失败、0 错误、0 跳过。

测试不使用真实业务书籍/账号，不连接应用配置中的 MySQL、Redis、MQ、ES 或模型。`EsRealSyncTest` 明确排除。
