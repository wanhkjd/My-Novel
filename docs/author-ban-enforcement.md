# 作家封禁权限校验

## 问题与状态语义

AuthorAuthStrategy 原先只检查缓存中是否存在作家信息，不检查 author_info.status。普通读者账号正常、作家账号被封禁时，已有 Token 仍能获得 authorId 并访问作家后台。即使增加状态判断，使用旧缓存也可能在封禁后错误放行、解封后错误拒绝。

数据库建表语句及 AuthorInfo 实体规定：作家状态 0 为正常，1 为封禁。它与普通读者的 user_info.status 独立，不沿用管理员 sys_user 的状态语义。

## 本次修改

- AuthorInfoCacheManager 增加不使用缓存的 getAuthorForAuth，直接按 user_id 查询当前记录；原 getAuthor 继续缓存一般资料查询，复用同一映射逻辑。
- AuthorAuthStrategy 先执行既有读者认证，再用当前作家状态鉴权：不存在返回 A0301；封禁返回新错误 A0302（作家账号已被封禁）；仅明确为 0 时设置 authorId，空值及未知状态不放行。
- AuthorServiceImpl.getStatus 同样查询当前记录，防止状态页面被旧缓存误导。
- 保持原协议：认证拒绝为 HTTP 200 + RestResp.code，不改为 HTTP 401/403。
- 保持注册和状态查询的作家认证豁免，但它们仍要求有效、未封禁的普通读者身份。已封禁作家重复注册不会重置原作家记录或解除封禁。
- 普通读者封禁校验、管理员 Token 命名空间、现有身份清理及一般资料缓存失效逻辑均保留。

每次受保护的作家请求增加一次当前作家记录查询；仓库建表脚本对 user_id 已有唯一索引 uk_userId，不需要数据库迁移。这里优先保证撤销权限可靠，而不是依赖缓存失效时序；本次不引入额外缓存版本或分布式锁。

## 回归验证（2026-10-11）

新增 AuthorBanAuthTest 共 25 项，采用生产 WebConfig 的路径及顺序、真实 JWT、认证策略、AuthorController、AuthorServiceImpl 和 Spring 缓存代理；数据库及图书业务使用 mock，缓存用内存实现。

覆盖：

1. 正常作家的 userId/authorId 仅在业务执行期间存在；拒绝请求也清除部分身份和复用线程的旧身份。
2. 被封禁作家无法到达小说列表、资料、小说发布、章节读写删除与章节列表等 8 个真实路由。
3. 空或非法 Token、同数字 ID 的管理员 Token、缺失作家、空或未知作家状态均不能获得权限。
4. 普通读者被封禁后不能访问作家注册、状态和写作入口；正常未注册读者仍可查询状态及注册，注册时使用认证身份而非请求体伪造的 userId。
5. 已封禁作家仍可查询自己的当前状态；重复注册不能解封。
6. 通过真实 AdminServiceImpl.updateAuthorStatus 方法修改模拟数据库、执行实际缓存失效，再人为回填旧缓存以模拟并发回填：同一个旧 Token 在封禁后被拒绝、解封后恢复；删除作家记录后也不能凭热缓存获得权限。

测试结果：

- 修复前：新增 25 项中 10 项通过、14 个 failure、1 个 error。唯一 error 是错误放行到真实资料控制器后访问空 mock 数据而触发的 ServletException；明确复现的断言还包括封禁后返回成功，以及当前状态被旧缓存覆盖。
- 修复后，独立提交分支：107 项通过，0 失败、0 错误、0 跳过。
- 修复后，包含用户既有未提交改动的隔离集成副本：130 项通过，0 失败、0 错误、0 跳过；额外用例不纳入本次提交。

## 部署与范围

源码同步后需要重新构建并重启后端，前端无需修改。本次只在独立工作树和临时集成副本构建，不改写运行中后端的 target/classes，也不合并或推送 main。

封禁/解封更新在数据库提交后，后续鉴权按当前状态执行；已经通过鉴权的在途请求不会被此补丁撤回或取消。本次不扩展到事务内再次鉴权、管理员状态修改参数校验或一般资料缓存的完整一致性治理。
