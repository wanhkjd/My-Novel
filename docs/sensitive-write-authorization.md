# 敏感写入口权限收口

## 范围与路由

| 操作 | 路由 | 权限 |
| --- | --- | --- |
| 全量书籍向量同步 | `POST /api/admin/ai/sync-vectors` | 使用现有管理员认证策略，校验管理员 Token、账号存在及禁用状态 |
| 旧前台全量同步入口 | `POST /api/front/ai/companion/sync-vectors` | 已移除，不保留兼容入口 |
| 图片上传 | `POST /api/front/resource/image` | 有效前台 Token，读者账号存在且未封禁；作家沿用前台 Token |
| 图片验证码 | `GET /api/front/resource/img_verify_code` | 保持匿名可访问，不阻断登录、注册 |

向量同步实现不变，仅将触发入口迁入管理员路由。前台资源路由默认纳入认证，当前仅精确排除验证码路径；静态图片访问路径未改动。普通 AI 对话、历史记录等仍使用原有前台认证。

## 认证约束

- 复用 `WebConfig → AuthInterceptor → FrontAuthStrategy/AdminAuthStrategy`，不在控制器重新实现 Token 校验。
- 前台与管理员使用不同的 Token 身份命名空间；即使账号数字 ID 相同也不能互换。管理员 Token 不可直接用于前台图片上传。
- 前台上传沿用不经用户信息缓存的 `getUserForAuth` 查询，保留读者封禁实时拦截能力。
- 沿用现有响应协议：认证失败通过 HTTP 200 响应中的 `RestResp.code` 表示，客户端不可只检查 HTTP 状态。
- 未发现前端对旧向量同步入口的调用；现有头像和封面上传使用前台 Token，无需本轮修改前端。

## 回归验证（2026-10-11）

新增 `SensitiveWriteAuthorizationTest`，以生产 `WebConfig` 的拦截范围及顺序、真实控制器、真实认证策略和 JWT 解析构建 MockMvc。数据库、缓存依赖和业务操作均使用 mock；不读取实际密钥，不调用模型、Redis 或 Elasticsearch，也不写入业务图片。

17 项用例覆盖：匿名/非法 Token、前后台 Token 不能混用、禁用/已删除管理员、封禁/已删除读者、合法同步和上传仅调用一次、旧入口不存在、验证码匿名访问、普通 AI 请求保持前台认证，以及同步请求结束后的身份清理。

验证结果：

- **RED**：仅添加新控制器和测试，尚未修改旧路由及拦截规则时，5 项负向回归断言全部失败，确认能够暴露旧入口仍存在、上传未鉴权的问题。
- **GREEN（提交分支）**：63 项后端测试通过，0 失败、0 错误、0 跳过，其中权限测试 17 项。
- **GREEN（本地集成副本）**：将同一补丁叠加到用户当前源码（含既有未提交改动）的隔离副本，86 项后端测试通过，0 失败、0 错误、0 跳过。多出的用例属于本地已有改动，不包含在本次权限提交中。

测试选择：

~~~shell
mvn "-Dtest=*,!EsRealSyncTest" test
~~~

实际验证使用 JDK 21、Maven 离线依赖及本机临时 settings。明确排除会操作真实 Elasticsearch 的 `EsRealSyncTest`；因此不是对真实向量写入链路的验收。构建仅在独立工作树和临时集成目录执行，未覆盖用户正在运行的后端编译产物。

## 部署与后续事项

- 源码更新后需要重新构建并重启后端，新路由和权限规则才会生效。
- 运维脚本如曾调用旧同步路径，应迁移到管理员路径并携带有效管理员 Token；不要将管理员 Token 嵌入公开前台代码。
- 本轮未实际触发全量向量同步，也未进行真实图片上传。
- 本轮只修复触发入口权限，不新增上传配额、同步任务互斥/去重、管理员细粒度角色授权；已有全局限流保持不变。
- SSE 异步身份传播、作家状态封禁、评论隐私、章节并发更新等其他审查项仍需单独处理。
